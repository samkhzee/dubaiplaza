Dubai Plaza Stock System

Simple staff website wireframes based on the product report. Four modules: Inventory, Sales + QR, Customers, Accounts. Goal: works like a proper shop system, feels lighter than Zoho Inventory (fewer screens, fewer clicks, no ERP clutter).

Design rule: One main action per screen. Search and Sell stay on top. Advanced things (Excel import, cost edit, exports) behind clear buttons — not 20 menus.
QR scope (simple): After each sale, system generates a QR on the bill/receipt page — scan opens sale summary (items, date, warranty ref). Optional: print sticker for sold laptop. Not a full barcode warehouse system in V1.

1 — Inventory management (Zoho-like power, simple UI)

Two types only: Laptops (one row = one physical machine) and Accessories (charger/RAM — quantity). No multi-warehouse, no 15 custom fields on list screen.

We keep (working properly)

  • Serialized laptops + qty accessories
  • Status: In stock / Sold / Returned
  • Excel import with preview
  • Unit cost, asking price, defects note
  • Stock count on search groups

We skip (Zoho complexity)

  • Multi-warehouse transfers
  • 50+ item custom fields on grid
  • Nested BOM / manufacturing
  • Heavy automation rules UI
  • Separate apps for every feature

Daily sale: Dashboard → Search laptop → Sell → Payment → Receipt + QR Stock in: Inventory → Import Excel → Confirm → Searchable Udhaar: Customers → Open → Receive payment OR Sale with partial Owner check: Accounts → Overview → Export (optional) Return: Sales → Bill → Return → Unit back to stock (rules)
